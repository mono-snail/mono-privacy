MonoProxy
Troubleshooting

Connected but no traffic?

Use MonoProxy's three connection states to identify whether the problem is the server, local network, client address, protocol, or authentication.

故障诊断

已连接，但没有流量？

根据 MonoProxy 的三个连接状态，判断问题出在服务器、局域网、客户端地址、协议还是认证。

Read the current state first

Listening

The server is ready, but no client has reached it. Check the network, address, port, and client proxy switch.

Client Connected

A client opened a connection, but usable proxy traffic has not passed yet. Check protocol choice, authentication, and the app generating traffic.

Traffic Verified

MonoProxy has relayed real traffic. If the client still fails, inspect the destination, client application, or network policy.

Check in this order

1

Confirm MonoProxy is listening

Start the server and keep MonoProxy in a state where it displays an IP address and port. If it is stopped, every client setting will fail.

2

Use the same local network

Connect the iPhone or iPad and the client to the same Wi-Fi or LAN. Guest Wi-Fi and client isolation can block devices from reaching each other.

3

Choose a reachable address

Enter the IP shown for the active local interface, not 127.0.0.1, a cellular address, or an address from a disconnected interface.

4

Match the client protocol

macOS needs both HTTP and Secure Web Proxy switches for browser traffic. Windows uses its manual HTTP/HTTPS proxy. SOCKS must be selected inside a client that supports SOCKS4 or SOCKS5.

5

Check authentication

If authentication is enabled, copy the current username and password into every relevant proxy entry. Saved credentials from an older profile can open a connection but fail the request.

6

Generate fresh traffic

Open a new browser tab and load a normal website after saving the proxy settings. Existing connections or cached pages may not create a new observable session.

7

Remove competing network layers

Temporarily disable another VPN, proxy, relay, firewall rule, or managed network profile on the client. Re-enable each layer after the direct local path works.

HTTPS remains encrypted. MonoProxy relays HTTPS CONNECT tunnels without installing a certificate or decrypting request and response content. Traffic Verified confirms relay activity, not content inspection.

If the state still does not advance

Run MonoProxy diagnostics and export a redacted report. Include the client platform, selected protocol, current state, and whether another VPN or managed network profile is active when contacting support.

先看当前状态

正在监听

服务器已经就绪，但客户端尚未到达。检查网络、地址、端口和客户端代理开关。

客户端已连接

客户端已建立连接，但尚未通过可用代理流量。检查协议选择、认证和实际产生流量的应用。

流量已验证

MonoProxy 已转发真实流量。若客户端仍失败，应继续检查目标站点、客户端应用或网络策略。

按顺序检查

1

确认 MonoProxy 正在监听

启动服务器，并确认 App 已显示 IP 地址和端口。服务器停止时，任何客户端配置都无法工作。

2

使用同一局域网

让 iPhone 或 iPad 与客户端连接到同一个 Wi-Fi 或局域网。访客网络和客户端隔离可能阻止设备互相访问。

3

选择可访问的地址

填写当前局域网接口显示的 IP，不要使用 127.0.0.1、蜂窝地址或已断开接口的地址。

4

匹配客户端协议

macOS 浏览流量需要同时开启 HTTP 和安全 Web 代理。Windows 使用手动 HTTP/HTTPS 代理。SOCKS 需要在支持 SOCKS4 或 SOCKS5 的客户端中选择。

5

检查认证

如果开启了认证，请把当前用户名和密码填入所有相关代理项。旧 Profile 留下的凭据可能能建立连接，但无法通过请求。

6

产生新的流量

保存代理设置后打开新的浏览器标签页并访问普通网站。已有连接或缓存页面可能不会产生新的可观察会话。

7

排除冲突的网络层

临时关闭客户端上的其他 VPN、代理、中继、防火墙规则或受管网络配置。直接局域网路径可用后，再逐项恢复。

HTTPS 内容仍保持加密。MonoProxy 通过 HTTPS CONNECT 转发隧道，不安装证书，也不解密请求和响应正文。“流量已验证”表示已发生转发，不代表查看了内容。

状态仍未推进

运行 MonoProxy 诊断并导出脱敏报告。联系支持时，请说明客户端平台、所选协议、当前状态，以及是否启用了其他 VPN 或受管网络配置。
